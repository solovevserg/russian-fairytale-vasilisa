# План рефакторинга

Цель: меньше мест, где хранится одно и то же; сцена описана данными, а не
кодом; вычисления — чистые функции от (состояние, время), побочные эффекты —
на краях (React-компоненты, `useFrame`, DOM). Поведение сайта при этом не
меняется: каждый шаг проверяется снимками глав «до/после» (см. «Сеть
безопасности»).

Порядок фаз — от дешёвых и безопасных к крупным. Каждую фазу можно
публиковать отдельно.

---

## Фаза 0. Сеть безопасности — до любых переделок

Без этого рефакторинг сцены проверяется только глазами.

1. **Эталонные снимки глав.** Временный `zz-shots.spec.ts` превратить в
   постоянный `tests/visual/chapters.spec.ts`: каждая остановка (титул,
   11 глав, титры) × два экрана (1280×800, телефон 390×844), `?instant&time=…`,
   без покачивания камеры. `toHaveScreenshot` с допуском. WebGL в CI
   нестабилен, поэтому запускать локально (`bun run test:visual`) перед
   публикацией крупных правок, эталоны хранить в репозитории.
2. **Управляемые часы.** `?clock=manual` + `window.__CLOCK__.advance(sec)` —
   все сцены по времени (всадники, уход с черепом, эпилог, подлёт в начале,
   подъём на титрах, кнопка «Вернуться в начало» через 6 с) тестируются без
   ожидания и детерминированно.
3. **Инварианты таймлайна** (юнит, быстрые) — см. раздел «Каких тестов не
   хватает».

## Фаза 1. Утилиты — в одно место (`src/lib/`)

Сейчас доменно-независимые функции живут рядом с тем, кто их первым
понадобил, и копируются:

| Что | Где сейчас |
|---|---|
| `smoothstep` / `smooth` | `terrain.ts`, `terrainSplat.ts`, `timeline.ts`, `departure.ts`, `homecoming.ts` + ещё ~10 мест вписано вручную `t * t * (3 - 2 * t)` |
| `lerpAngle` | `timeline.ts`, `homecoming.ts`, `intro.ts` |
| `lerp`, `clamp` | `timeline.ts` и вручную `Math.min(Math.max(…))` повсюду |
| сглаживание по кадрам `1 - Math.exp(-k * Math.min(delta, 0.1))` | `CameraRig` (×3), `Vasilisa`, `stepLimited`, … |
| разбор `?параметров` адреса | `debugFlags`, `lang`, `autoReader`, `CameraRig`, `quality`, `sceneStore` |
| `localStorage` в `try/catch` | `lang.ts`, `theme.ts`, ещё в `index.html` |
| закрытие по щелчку мимо / Escape | `LangMenu` |
| подписка на прокрутку `.story` | `SwipeHint`, `BackToStart`, `useScrollProgress` |
| римские цифры | `StoryColumn` |

Правило для `src/lib/`: **ни одного импорта из `story/`, `scene/`, `ui/`,
`i18n/`** (проверяется правилом biome `noRestrictedImports` или простым
юнит-тестом по импортам). Всё там — чистые функции с тестами.

```
src/lib/
  math.ts        clamp, clamp01, lerp, inverseLerp, smoothstep, smoothstep01,
                 lerpAngle, wrapAngle, remap
  easing.ts      ease-кривые, если их станет больше одной
  damp.ts        damp(current, target, rate, dt) — экспоненциальное догоняние;
                 ramp(current, on, upSec, downSec, dt) — линейный 0..1 туда-обратно;
                 approachLimited(…) — нынешний stepLimited без знания о главах
  curve.ts       catmull(points) → { at(u), tangentAt(u), length } поверх three
  vec.ts         операции над кортежами Vec3/Vec2 (add, scale, mix, rotateY)
  url.ts         urlParams() — один раз; flag(name), number(name), string(name)
  storage.ts     persisted<T>(key, parse) → { read(), write(v) } с try/catch
  roman.ts       toRoman
  hooks/
    useOutsideClose.ts   щелчок мимо + Escape
    useScrollState.ts    подписка на прокрутку контейнера с rAF
```

Затем `debugFlags.ts` превращается в один объект настроек из адреса
(`time`, `quality`, `lang`, `readtime`, `instant`, `no*`) — единственный
источник; остальные модули читают его.

Объём: механическая замена, тесты не должны меняться. Риск — низкий.

## Фаза 2. Один источник правды для данных истории

### 2.1 Список глав

Сейчас порядок глав задан дважды: `id` в `src/i18n/chapters/ru.ts` и `id` в
`KEYFRAMES`. Они связаны только индексом, а `id` — просто `string`.

- `story/chapterIds.ts`: `export const CHAPTER_IDS = ["prologue", …, "epilogue"] as const; type ChapterId`.
- Сцена: `SCENES: Record<ChapterId, SceneKeyframe>`; массив `KEYFRAMES`
  выводится из `CHAPTER_IDS.map(id => SCENES[id])`. Пропущенная или лишняя
  глава — ошибка типов, а не тихий сдвиг.
- Тексты: `Record<ChapterId, { title, paragraphs }>` на каждый язык.
- Подписи «Глава первая…», навигация `STOPS`, якоря `#fire` — выводятся из
  `CHAPTER_IDS`.
- `ORDINALS_*` — перенести в файлы языков рядом с текстами (сейчас все
  четыре языка в `content.ts`).

### 2.2 Места на карте (`story/places.ts`)

Координаты, замеренные «по месту», повторяются:

- `HOME_SPOT = onPath(51, 0, -2.6)` в `homecoming.ts` и тот же `onPath(51, 0, -2.6)` в `atHome` (`keyframes.ts`);
- Баба Яга и Василиса в «Черепе» смотрят друг на друга: `atan2(3.1, 2.1)` и
  `atan2(-3.1, -2.1)` записаны вручную;
- `heightAt(0, 0) + PORCH.height`, `[0, 4.2, 0]` (HUT), `[0, 3, 0]`
  (finalTarget), центр избушки в `AudioDirector` (`+ 4.5`);
- камера над избушкой считается дважды: `homecomingCamera` и `creditsCamera`
  повторяют расчёт `fx/fz`.

Всё это — именованные места (`HOME_DOOR`, `GATE`, `PORCH`, `HUT_TOP`,
`BABA_STAND`, `EPILOGUE_FINAL_CAMERA`) с выводимыми связями
(`facing(a, b)`). Ключевые кадры ссылаются на места по имени.

### 2.3 Всадники

Один всадник описан в пяти местах: путь и длительность — `RIDER_PATHS`
(`keyframes.ts`), цвета — `Riders.tsx`, смена света — `RIDER_LIGHT`
(`lightDelay.ts`), темп по уровню качества — `riderClock.ts`, глава —
`rider` в кадре. Свести в один `RIDERS: Record<RiderColor, RiderSpec>`
(`path, duration, delay, light, palette, pace`). Кадр главы ссылается на
него, а темп по уровню качества — один параметр `pace` в настройках качества
(`QUALITY[tier].riderPace`), без проверки `tier === …` в коде.

### 2.4 Значения по умолчанию

`timeline.ts` разбирает пропуски на каждом кадре: `k.hut ?? true`,
`k.houseLit ?? true`, `k.fog ?? 1`, `a.onward ?? 0`. Ввести
`resolveKeyframe(partial) → Keyframe` с полным набором полей один раз при
загрузке; дальше в коде ни одного `??`. Типы: `KeyframeInput`
(необязательные поля) и `Keyframe` (все обязательные).

### 2.5 Замеры моделей

`LEFT_PALM`, `LANTERN_GRIP`, `MODEL_OFFSET`, `FACE_Y`, `PORCH` — это
измерения вершин `.glb`, сделанные вручную. `scripts/prepare-models.ts`
уже читает вершины: пусть пишет рядом `vasilisa.meta.json` и
`hut.meta.json` (рост, смещение оси, ладонь, крыльцо). Перегенерировали
модель — замеры обновились сами.

### 2.6 Документация

`docs/scenario.md` дублирует комментарии ключевых кадров, а `SPEC.md` —
числа (`transition 6`, `rise 17`). Числа в документации заменить ссылками на
имена констант; таблицу сценария можно генерировать скриптом
(`bun scripts/scenario.ts`) из `SCENES` + текстов, либо хотя бы юнит-тест:
каждый `ChapterId` упомянут в `scenario.md`.

## Фаза 3. Декларативная сцена

### 3.1 Разбить `keyframes.ts` (546 строк)

```
story/
  types.ts            SceneKeyframe, VasilisaState, Vec3
  places.ts           места (2.2)
  riders.ts           RIDERS (2.3)
  flights.ts          BABA_YAGA_FLIGHT, BABA_YAGA_STAND
  scenes/
    prologue.ts … epilogue.ts   по файлу на главу: кадр + комментарий режиссуры
    index.ts          SCENES, KEYFRAMES
```

### 3.2 Присутствие объектов — данными

`Hut`, `Torch`, `Fence`, `Garden`, `House` каждый в своём `useFrame` читают
`currentSample` и зовут `setShown`. Заменить одним компонентом:

```tsx
<Presence when={(s) => s.hut}><Hut /><Torch /><Fence /></Presence>
<Presence when={(s) => s.house}><House /><Garden /></Presence>
```

Свет внутри гасится интенсивностью (как сейчас) — это знание остаётся в
одном месте, в `Presence`.

### 3.3 Эпизоды по часам вместо глобальных часов

Сейчас «то, что идёт по времени с входа в главу», разнесено по модулям и
связано общими изменяемыми объектами:

- `homecomingClock` заводит `Vasilisa`, читает `CameraRig`;
- `riderStarts` пишет `Riders`, читает `CameraRig` (через `delayedTimeProgress`);
- уход с черепом (`departure`) и подлёт в начале (`intro`) отслеживаются
  отдельно и в `Vasilisa`, и в `CameraRig`, у обоих своя проверка
  `sceneProgress.value < 0.02`;
- `onward` — свой таймер в `Vasilisa`.

Предложение: кадр главы объявляет эпизод —
`episode: { kind: "rider", color: "black" } | { kind: "departure" } | { kind: "homecoming" } | { kind: "onward", metres: 2.5 }`.
Один «режиссёр» (`story/director.ts`) хранит единственное событие на
главу — когда сцена вошла в неё (`enteredAt[chapter]`), — и чистой функцией
`direct(sample, enteredAt, now) → Frame` выдаёт всё сразу: позу Василисы,
камеру, положение всадника, задержку света. Компоненты только рисуют
`Frame`. Эпизоды тестируются как функции `(t) → pose`, без React.

### 3.4 CameraRig — конвейер слоёв

240 строк в `useFrame`: таймлайн → эпилог → титул → титры → подлёт → параллакс
→ высота над землёй. Каждый шаг сделать чистой функцией
`(shot, ctx) → shot`, а сглаженные величины (`staged`, `lightProgress`,
`epilogue`, `title`, `rise`, `intro`) — через `damp`/`ramp` из `lib/`:

```ts
const LAYERS = [timelineShot, epilogueShot, titleShot, creditsShot, introShot, parallaxShot, keepAboveGround];
const shot = LAYERS.reduce((s, layer) => layer(s, ctx), baseShot);
```

Порядок слоёв — данные, каждый слой тестируется отдельно.

### 3.5 Vasilisa.tsx

То же для героини: выбор источника положения (`entering ? … : leaving ? … :
returning ? …`) — таблица `pose → motion(t)`; сглаживание скачков — общий
слой; `Face` и замеры — в отдельные файлы (`VasilisaFace.tsx`,
`vasilisaRig.ts`).

### 3.6 Состояние кадра

`currentSample`, `sceneProgress`, `riderStarts`, `homecomingClock`,
`pointer`, `drift`, `windUniforms` — изменяемые объекты уровня модуля.
После 3.3 остаётся один `frame` (результат `direct`), его пишет одно место
(`StoryDirector`), читают все. Для тестов — `createFrame()`, без глобалей.

### 3.7 Прокрутка → положение чтения

`useScrollProgress` считает `title`, `credits`, `edge` прямо в обработчике и
передаёт в `setProgress(progress, title, edge, credits)` позиционными
аргументами; `activeChapter` выводится в сторе. Вынести чистую
`readingPosition(anchors, focus, start, credits) → ReadingPosition` (с
тестами), хук только измеряет DOM. Стор хранит объект целиком.

## TSDoc на всё публичное

Сейчас примерно из 206 экспортов у 76 нет комментария (больше всего в
`keyframes.ts`, `sounds.ts`, `terrain.ts`, `quality.ts`,
`forest/variants.ts`, `scrollAxis.ts`, `timeline.ts`), а у многих
документированных функций не описаны параметры и единицы измерения. Поля
интерфейсов и методы классов (`AudioEngine`, `AutoReader`) покрыты
неравномерно.

**Правила:**

- Комментарий `/** … */` у каждого экспорта: функции, константы, типа,
  интерфейса, класса; у каждого поля экспортируемого интерфейса и публичного
  метода/свойства класса. Неэкспортируемое — по желанию, если не очевидно.
- Первая фраза — что это (она видна в подсказке редактора). Дальше —
  зачем и какие есть ограничения.
- `@param` и `@returns` — когда имя и тип не говорят всего: **единицы**
  (м, с, часы, рад, доля 0..1), система координат (мир / от избушки по
  тропе / локальная модели), что значит `NaN`/`null`/`-1`.
- `@example` — для геометрических помощников (`onPath`, `pathFrame`,
  `facing`) и утилит `lib/`.
- `@see` — связь с документацией (`docs/scenario.md`) и с парным модулем,
  вместо пересказа.
- Язык — русский, как сейчас; теги — стандартные TSDoc.
- Компоненты React: комментарий у компонента и у полей его `Props`.

**Как не дать покрытию сползти:** TypeDoc с проверкой
`--validation.notDocumented` и `--treatValidationWarningsAsErrors` в CI
(`bun run docs:check`). Попутно он собирает справочник API (`docs/api/`,
можно публиковать вместе с сайтом). Biome такого правила не имеет, а
ESLint ради одного правила тащить не стоит.

Делать вместе с фазами 1–3: каждый перенесённый или новый модуль сразу
получает полный TSDoc, а проверка включается на `src/lib/` и `src/story/`,
затем на всё остальное.

## Каких тестов не хватает

**Юнит (чистые функции, быстрые):**

- *Кадр на телефоне.* `framing.test` проверяет, что Василиса в кадре, но без
  учёта формы экрана. Нужно для каждой главы × {16:10, 9:19.5}: героиня и
  всадник/Баба Яга в видимой части **над карточкой с текстом** (нижние ~40 %
  на телефоне). Больше половины правок последних недель — именно об этом.
- *Непрерывность.* Прогон таймлайна с шагом 0.005: скорость Василисы и
  камеры ограничена (нет телепортов), поворот без скачков, камера не внутри
  избы, избушки, забора (по ограничивающим коробкам).
- *Флаги.* `houseLit` гаснет в «Огне» и не загорается до конца; избушки
  нет до «Поляны»; глаза черепов только с «Чёрного всадника».
- `stepScene`/`easeScene`: переход длится не меньше `transition`; назад и
  транзитом — в 4 раза быстрее; монотонность.
- `readingPosition` (после 3.7): титул, титры, `edge`.
- Слои камеры (после 3.4): титры не переворачивают кадр (взгляд вниз,
  избушка в верхней половине) — то, что ломалось дважды.
- Эпизоды (после 3.3): уход с черепом заканчивается на ~2/3 пути, эпилог
  начинается с того места, где она была.
- `riderDuration` по уровням качества; `quality` по устройству.
- Навигация: `STOPS`, разбор `#hash`, `useStop`.
- `lib/` целиком.
- Скрипты подготовки: раскраска зон Василисы (сколько треугольников в
  каждой зоне — снимок), размер моделей.

**E2E:**

- Эталонные снимки глав (Фаза 0).
- С управляемыми часами: всадник проскакал → свет сменился; кнопка
  «Вернуться в начало» через 6 с и возврат на титул.
- Глубокие ссылки на каждую главу (`#tasks` открывает «Задачи» и на
  телефоне, и на компьютере).
- `prefers-reduced-motion`.
- Доступность: `@axe-core/playwright` на титуле и одной главе.
- Дым производительности: уровень low с замедлением CPU (CDP), средний
  кадр не хуже порога.
