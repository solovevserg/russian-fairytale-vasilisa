# Избушка на курьих ножках — спецификация

Интерактивная 3D-история для веба по сказке «Василиса Прекрасная».
Документ описывает **что** мы строим и **как** — на уровне архитектуры и договорённостей.
Сюжет по главам — в [scenario.md](scenario.md), сторонние ресурсы и лицензии — в [assets.md](assets.md).

Статус: черновик v0.2 (2026-10-10).

---

## 1. Концепция

- Экран разделён на две части: **слева** — 3D-сцена (WebGL), **справа** — текст сказки, который читатель прокручивает.
- Прокрутка текста — единственный «контроллер» сцены. По мере чтения меняются:
  - время суток (свет, небо, туман, цвет);
  - положение и угол камеры;
  - состав сцены — появляются и исчезают персонажи и объекты (Василиса, Баба Яга в ступе, всадники, черепа на частоколе);
  - атмосферные эффекты (ветер, туман, светлячки, дым из трубы);
  - звуковой эмбиент (см. §6).
- Сцена: небольшой участок густого дремучего леса, поляна, в центре — избушка на курьих ножках.
- Жанр — арт-проект, «скроллителлинг». Не игра: никакого управления, кроме прокрутки и кнопки звука (плюс, возможно, лёгкий параллакс от мыши).

### Сюжет

Основа — сказка «Василиса Прекрасная» в записи А. Н. Афанасьева («Народные русские сказки», № 104). Текст XIX века — общественное достояние. Используем его в сокращённой и слегка адаптированной редакции; правки фиксируются в [scenario.md](scenario.md).

Сказка удобно ложится на смену времени суток: Василиса встречает трёх всадников — белого (утро), красного (день) и чёрного (ночь).

### Визуальный стиль

- **Полуреалистичный тёмный лес**: PBR-материалы, реалистичные пропорции, густой туман, глубокие тени, приглушённая палитра в сумерках и ночью.
- **Днём — палитра Билибина**: насыщенные охры, киноварь, изумрудная и бирюзовая зелень, золотистое небо. Достигается цветокоррекцией (LUT по времени суток) и подбором цветов света/неба/тумана, а не сменой моделей.
- Избушка и персонажи — реалистичные модели, не мультяшные.

### Цели

1. Атмосфера и визуальное качество важнее реализма.
2. Плавность: 60 FPS на среднем ноутбуке, без рывков при прокрутке.
3. Текст читается и без 3D (доступность, слабые устройства).

### Не цели (на первую версию)

- Свободное управление камерой пользователем.
- Многоязычность (текст только на русском; архитектура не должна мешать добавить позже).

## 3. Макет страницы

### Десктоп (ширина ≥ 1024 px)

```text
┌──────────────────────────────┬───────────────────┐
│                              │  Глава I          │
│                              │  текст…           │
│      3D-сцена (sticky,       │                   │
│      100vh, ~60% ширины)     │  Глава II         │
│                              │  текст…           │
│  [🔊]                        │       ↓ скролл    │
└──────────────────────────────┴───────────────────┘
```

- Canvas закреплён (`position: sticky`/`fixed`), прокручивается документ (нативный скролл — для доступности и привычного поведения).
- Соотношение колонок — примерно 60/40, настраивается CSS-переменной.
- Кнопка звука — в углу сцены, всегда видна.

### Мобильные и планшеты (< 1024 px)

- Сцена — полноэкранный фон, текст идёт поверх на полупрозрачных «карточках» по главам.
- Пониженное качество графики по умолчанию (см. §8).

### Типографика

- Шрифт с хорошей кириллицей и «сказочным» характером для заголовков (кандидаты: Ruslan Display; для основного текста — PT Serif или Lora). Шрифты лежат в проекте (self-hosted), без внешних CDN.
- Буквицы в начале глав в духе Билибина — по желанию.

## 4. Модель «скролл → сцена»

### 4.1. Главы и ключевые кадры

Текст разбит на **главы** (секции). Каждой главе соответствует **ключевой кадр** сцены — набор параметров:

```ts
interface SceneKeyframe {
  id: string;                    // 'ch1-white-rider'
  timeOfDay: number;             // 0..24, часы — солнце, небо, свет, палитра, эмбиент
  camera: {
    position: [number, number, number];
    target: [number, number, number];
    fov: number;
  };
  fog: { color: string; density: number };
  wind: number;                  // сила ветра для травы, деревьев и звука ветра
  actors: Record<string, ActorState>; // видимость, анимация, позиция на пути
  hut: { windowsLit: boolean; skullsLit: boolean };
  post: { bloom: number; vignette: number; lutMix: number };
  audio: { layers: Record<string, number>; cues?: string[] }; // громкости слоёв, разовые звуки
}
```

Все ключевые кадры описаны **данными** (`src/story/keyframes.ts`), а не кодом — сюжет можно править, не трогая рендеринг.

### 4.2. Вычисление прогресса

- Каждая глава в DOM — `<section data-keyframe="…">`.
- Глобальный прогресс `p ∈ [0, N-1]` — дробный индекс: целая часть — текущая глава, дробная — доля перехода к следующей. Вычисляется по положению секций относительно центра вьюпорта (scroll + `ResizeObserver`), хранится в zustand.
- Сцена в `useFrame` берёт два соседних ключевых кадра и интерполирует параметры с easing. Камера — по сплайну (CatmullRom) через позиции всех ключевых кадров, чтобы пролёт был плавным.
- Демпфирование (`maath/easing.damp`) поверх прогресса — рывки колесом мыши не превращаются в рывки камеры.

### 4.3. События

Помимо непрерывных параметров — **дискретные события** при пересечении порога: старт анимации, появление персонажа, разовый звук. События обратимы — при прокрутке назад состояние откатывается (разовые звуки при этом не проигрываются повторно в обратную сторону).

### 4.4. Анимация персонажей от скролла

Персонажи двигаются по заранее заданным траекториям (сплайнам), и позиция на траектории привязана к прогрессу главы. Циклические анимации (бег Василисы, покачивание ступы) идут во времени, но их скорость модулируется скоростью прокрутки — при остановке скролла персонаж замедляется до idle.

## 5. Сцена

### 5.1. Композиция

- Поляна радиусом ~15–20 м в центре, вокруг — плотное кольцо леса глубиной ~40–60 м, дальше — силуэты и туман, скрывающие край мира.
- Тропинка из леса к избушке — по ней бежит Василиса.
- Маршрут камеры проектируется вместе с расстановкой леса: граница мира никогда не видна.
- Детерминированность: вся процедурная генерация использует фиксированный seed — сцена одинакова у всех и в визуальных тестах.

### 5.2. Деревья (ez-tree)

- 4–6 **вариантов** деревьев (ель, сосна, берёза, старый дуб, сухое дерево), сгенерированных ez-tree с фиксированными seed. Тёмный еловый лес преобладает.
- Уровни детализации:
  - **Ближний план** (кольцо у поляны, ~20–40 деревьев) — полные меши ez-tree, листва с alpha-test, тени.
  - **Средний план** — те же варианты через `InstancedMesh`, упрощённые тени или без них.
  - **Дальний план** — билборды/импостеры или силуэты в тумане.
- Генерация в рантайме (при необходимости в Web Worker) **или** запекание в glb при сборке — решим по замерам на этапе 2.
- Ветер — смещение вершин листвы и ветвей в шейдере (`onBeforeCompile` материала ez-tree).
- Мох и лишайник на стволах — для «дремучести».

### 5.3. Трава и подлесок

- Трава: `InstancedMesh` из лезвий (5–7 вершин), десятки тысяч инстансов, плотность падает к краю поляны и под деревьями. Ветер, вариация цвета и высоты.
- Подлесок: папоротники, кусты, мухоморы, пни, камни, бурелом — простые модели или процедурные, разбросанные по маске плотности (Poisson disk).
- Земля: рельеф из шума, PBR-текстура лесной подстилки, тропинка.

### 5.4. Избушка на курьих ножках

- Готовая **реалистичная** модель с PBR-материалами. Кандидаты и требования — в [assets.md](assets.md).
- Желательно с ригом ног (переминается, приседает). Если рига нет — дорабатываем в Blender или ограничиваемся статикой с лёгким «дыханием».
- Окна с эмиссией (свет внутри ночью), дым из трубы (частицы/спрайты).
- **Частокол из костей с черепами** — по тексту сказки; глаза черепов светятся ночью и гаснут на рассвете.

### 5.5. Персонажи (v1)

| Персонаж | Что делает | Требования к ассету |
| --- | --- | --- |
| **Баба Яга** | прилетает в ступе, правит пестом (в тексте — «пестом погоняет, помелом след заметает») | реалистичная модель старухи в ступе + пест + помело; анимация может быть простой (покачивание, полёт по сплайну), ступа и помело — отдельные объекты |
| **Василиса** | бежит по тропинке через лес (к избушке и обратно домой с черепом-светочем) | риггованная девушка в сарафане, анимации бега и idle; бег можно взять из Mixamo и ретаргетить |

Опционально (если останется время): три всадника (белый, красный, чёрный) — проносятся по краю леса; куколка Василисы; чёрный кот.

### 5.6. Время суток и атмосфера

- Небо: кастомный градиентный купол (для контроля палитры Билибина) + звёзды и луна ночью; `Sky` из drei — как запасной вариант.
- Направленный свет (солнце/луна) с тенями, позиция вычисляется из `timeOfDay`.
- Палитры по времени суток (рассвет, день, закат, сумерки, ночь): цвета света, неба, тумана и LUT. Ночь и сумерки — холодные, приглушённые; день — тёплые насыщенные «билибинские».
- Туман — экспоненциальный + лучи света между деревьями на рассвете (опционально).
- Частицы: светлячки ночью, пыльца в лучах днём, падающие листья, искры от черепов.

## 6. Звук

Звуковой эмбиент — **обязательная часть v1**.

### 6.1. Состав

- **Эмбиент-слои** (зацикленные, бесшовные), громкость каждого — параметр ключевого кадра:
  - утро — птицы, лёгкий ветер;
  - день — листва, насекомые, далёкая кукушка;
  - вечер/ночь — сверчки, сова, скрип деревьев, сильный ветер;
  - «волшебный» слой — тихий музыкальный дрон/тембр для напряжённых моментов.
- **Позиционные источники** (`PositionalAudio`): потрескивание огня в черепах, скрип избушки, свист ступы при пролёте Бабы Яги, шаги Василисы.
- **Разовые события**: топот всадника, удар песта, хлопок двери.

### 6.2. Поведение

- Браузеры запрещают автозапуск звука без действия пользователя. Звук по умолчанию **выключен**; на экране загрузки — кнопка «Начать со звуком» / «Без звука», дальше — переключатель в углу сцены. Выбор запоминается в `localStorage`.
- Переходы между слоями — кроссфейд, привязанный к прогрессу (как и остальные параметры).
- Пауза звука при скрытии вкладки.
- `prefers-reduced-motion` звук не отключает, но разовые резкие звуки делаются тише.

### 6.3. Технически

- Форматы: Opus в контейнере WebM (`.webm`) с запасным AAC (`.m4a`) для старых Safari.
- Бюджет: эмбиент-слои по 30–60 с, суммарно < 5 МБ; грузятся после первого кадра, не блокируют показ сцены.
- Источники: freesound.org (CC0 / CC-BY), Sonniss GDC bundle (бесплатные лицензии) — каждый файл заносится в [assets.md](assets.md).

```text

    timeline.ts            # интерполяция кадров, события (чистые функции — покрыты bun test)
  state/

  hooks/

    CameraRig.tsx

    Forest/                # ez-tree, инстансинг, LOD
    Grass/                 # шейдер травы
    Ground.tsx
    Hut.tsx                # избушка + частокол
    Actors/                # BabaYaga.tsx, Vasilisa.tsx
    Effects.tsx            # постобработка
  audio/
    AudioDirector.tsx      # слои, кроссфейды, события по таймлайну
  ui/
    StoryColumn.tsx
    Chapter.tsx
    Loader.tsx             # прогресс загрузки + выбор «со звуком / без»
    SoundToggle.tsx
    Fallback.tsx           # без WebGL
  styles/
public/
  models/                  # сжатые glb
  textures/
  audio/
  fonts/
docs/
tests/
  unit/                    # bun test
  e2e/                     # Playwright
```

Принципы:

- **Данные отдельно от рендера**: сюжет и ключевые кадры — чистые данные; логика интерполяции — чистые функции.
- Тяжёлые части сцены грузятся лениво (`Suspense`, `useGLTF.preload`), есть экран загрузки с прогрессом.
- Флаг отладки `?debug` — панель (leva) для подбора параметров кадров, r3f-perf, кнопка «скопировать текущий кадр» для удобного авторинга.

## 8. Производительность

Бюджеты (ориентиры, уточняются после прототипа):

| Метрика | Цель |
| --- | --- |
| FPS, десктоп со встроенной графикой | ≥ 50, цель 60 |
| FPS, современный смартфон | ≥ 30 |
| Draw calls | < 200 |
| Треугольники в кадре | < 1.5 M (десктоп) |
| Объём загрузки (gzip, без шрифтов) | < 20 МБ, до первого кадра < 5 МБ |
| Время до интерактивного текста | < 2 с (текст не ждёт 3D) |

Механизмы:

- Уровни качества (`low / medium / high`): плотность травы, число деревьев, разрешение теней, постобработка, `dpr`. Автовыбор через `PerformanceMonitor` из drei, деградация при падении FPS.
- Рендер на паузе, когда вкладка не видна.
- Инстансинг везде, где объектов больше одного; общие материалы; KTX2-текстуры; модели персонажей — LOD или децимация до разумных размеров.

## 9. Доступность и фолбэки

- Текст — семантичный HTML: читается скринридером, работает поиск по странице и выделение.
- Нет WebGL или ошибка инициализации → статические иллюстрации (заранее отрендеренные кадры по главам).
- `prefers-reduced-motion` → без пролётов камеры: смена кадров через кроссфейд, ветер ослаблен.
- Canvas помечен `aria-hidden`, у глав — нормальные заголовки, у кнопки звука — подпись.

## 10. Качество кода и тесты

### Biome

- `biome.json` в корне: форматирование + линтинг (recommended + строгие правила для TS).
- `bun run check` = `biome check .`; в CI — `biome ci .`.

### Юнит-тесты (`bun test`)

- `timeline.ts`: интерполяция кадров, глава по прогрессу, обратимость событий, громкости аудиослоёв.
- Генераторы расстановки (Poisson disk, детерминированность по seed).

### Playwright (e2e)

- **Смоук**: страница открывается, нет ошибок в консоли, canvas появился, текст всех глав на месте.
- **Скролл → состояние**: прокрутка до главы N меняет текущую главу (в тестовом режиме состояние доступно через `window.__STORY__`) и параметры кадра.
- **Визуальные снимки**: скриншот сцены на каждом ключевом кадре (фиксированный seed, анимации заморожены через `?test`), сравнение с эталоном с допуском. Эталоны генерируются в Linux-контейнере CI.
- **Звук**: кнопка переключает состояние, `AudioContext` создаётся только после действия пользователя.
- **Фолбэк**: при отключённом WebGL показываются иллюстрации.
- **Мобильный макет**: проект Playwright с эмуляцией телефона.
- Браузеры: Chromium (основной, WebGL через SwiftShader в CI); Firefox/WebKit — для смоука.

### Скрипты (`package.json`, запуск через `bun run`)

```text
dev, build, preview, check, typecheck, test (bun test), test:e2e (playwright), assets:optimize
```

## 11. CI/CD (GitHub Actions)

- `ci.yml` — на каждый PR и push:
  1. `oven-sh/setup-bun` + `bun install --frozen-lockfile`
  2. `bunx biome ci .`
  3. `bunx tsc --noEmit`
  4. `bun test`
  5. `bun run build`
  6. Playwright (браузеры кешируются), отчёт и диффы скриншотов — артефактом при падении.
- `deploy.yml` — на push в `main`: сборка и публикация через `actions/upload-pages-artifact` + `actions/deploy-pages`.
- Ветка `main` защищена, изменения — через PR с зелёным CI.
- Dependabot для Actions (и для npm-зависимостей — Dependabot поддерживает `bun.lock`).
